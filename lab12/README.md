```bash

```

Если команда `python` не найдена, используйте `python3`.

## Назначение проекта и предметная область

Проект представляет собой законченное консольное приложение для учёта и ведения личного списка книг для чтения (**Вариант 2**).

Основные характеристики предметной области:
- `title` — название книги (строка без краевых пробелов);
- `category` — жанр или тематическая категория (например, «Программирование», «Алгоритмы», «Фантастика»);
- `amount` — объём книги в страницах (целое неотрицательное число $\ge 0$, единица измерения: «стр.»);
- `completed` — статус прочтения книги (`True` — прочитана, `False` — не прочитана);
- `id` — уникальный положительный целочисленный идентификатор книги. Для первой записи равен `1`, для каждой последующей вычисляется как максимальный существующий ID плюс один.

## Архитектура и структура модулей

```text
lab12/
    main.py           # Консольный интерфейс: цикл меню, ввод, валидация
    logic.py          # Бизнес-логика: проверка данных, добавление, поиск, статистика
    storage.py        # Слой хранения: чтение и запись JSON без ввода/вывода
    test_logic.py     # Модульные тесты бизнес-логики (assert)
    test_storage.py   # Модульные тесты слоя хранения (TemporaryDirectory)
    gui.py            # Дополнительный графический интерфейс (Tkinter)
    data.json         # Файл данных с начальным набором книг
    README.md         # Документация и отчет о тестировании
```

### Разделение ответственности модулей
1. **`logic.py` (чистая бизнес-логика)**:
   - Не выполняет консольного ввода/вывода (`input()`, `print()`) и не работает напрямую с файлами на диске.
   - `validate_records(records)` — строгая проверка структуры списка и типов полей.
   - `generate_next_id(records)` — вычисление следующего доступного ID.
   - `add_record(records, title, category, amount)` — добавление новой книги (статус `False`).
   - `find_records(records, query)` — поиск по подстроке в названии без учёта регистра.
   - `set_completed(records, record_id, completed)` — явная установка статуса по ID.
   - `delete_record(records, record_id)` — удаление книги без перенумерации оставшихся ID.
   - `statistics(records)` — расчёт общего числа книг, прочитанных/непрочитанных, суммы страниц и распределения страниц по категориям (по алфавиту).
2. **`storage.py` (слой сохранения данных)**:
   - `load_records(path)` — чтение JSON-файла в кодировке UTF-8 и валидация через `validate_records`.
   - `save_records(path, records)` — сохранение списка в JSON с форматированием (`ensure_ascii=False, indent=2`).
3. **`main.py` (пользовательский интерфейс)**:
   - Организует текстовое меню (пункты 1–8), диалог с пользователем, валидацию пользовательского ввода и обработку исключений.
4. **`gui.py` (дополнительный интерфейс)**:
   - Окно на базе `tkinter` с таблицей `ttk.Treeview`, строкой поиска по подстроке (использует `find_records`) и выводом сводной статистики.

## Сценарии приёмки

| Сценарий | Ожидаемое поведение | Фактический результат |
|---|---|---|
| **Файла нет** | Начинается с пустого списка, меню доступно | Сообщение: `Файл данных не найден. Начат новый список.`, меню доступно |
| **JSON содержит `[]`** | Список пуст, статистика: все количества и сумма равны 0 | `Всего книг: 0`, `Прочитано: 0`, `Не прочитано: 0`, `Всего страниц: 0` |
| **Добавлены записи с количеством 4 и 2, вторая завершена** | Всего 2, выполнена 1, невыполнена 1, сумма 6 | `Всего: 2, Прочитано: 1, Не прочитано: 1, Всего страниц: 6` |
| **Название введено как `  Python  `** | Пробелы по краям удалены: сохранено `Python` | В списке и файле сохранено строго `Python` |
| **Поиск `PY` при названии `Python`** | Регистронезависимый поиск находит запись | Книга `Изучаем Python` найдена и выведена в таблице |
| **Пустое название, `amount=-1`, `amount=abc`** | Повторный ввод при ошибке, лишняя запись не создаётся | Выводятся сообщения об ошибках, запрос повторяется до корректных данных |
| **Изменение статуса неизвестного ID** | Сообщение об ошибке, данные не изменены | Выведено: `Ошибка: книга с ID=... не найдена`, список не изменился |
| **Удаление отменено** | При ответе, отличном от `да`, удаление отменяется | Выведено: `Удаление отменено.`, книга осталась в списке |
| **Удалена запись с ID 1 из списка с ID 1 и 2** | Оставшаяся запись сохраняет ID 2; следующая новая получает ID 3 | Запись 2 сохранила ID 2; при добавлении новой книги присвоен ID 3 |
| **Сохранение и перезапуск** | Все поля, статусы и значения полностью восстанавливаются | Загружен идентичный список записей из `data.json` |
| **Повреждённый JSON или некорректный ID** | Запуск прекращается с сообщением, файл на диске не перезаписывается | Программа выводит ошибку и завершает работу, файл `data.json` остаётся нетронутым |
| **Ошибка сохранения** | Сообщение об ошибке, программа остаётся в меню | При возникновении `OSError` выводится сообщение, программа не падает |

## Жизненный цикл записи: от ввода до JSON и обратно

1. **Ввод пользователем (`main.py`)**:
   - Пользователь выбирает пункт 2 («Добавить запись»).
   - Функция `prompt_non_empty_string` запрашивает название `  Совершенный код  `, очищает его методом `.strip()` до `'Совершенный код'`.
   - Запрашивается жанр `'Программирование'` и число страниц `600` (проверяется, что `int >= 0`).
2. **Создание и валидация в памяти (`logic.py`)**:
   - Функция `generate_next_id(records)` определяет максимальный текущий `id` (например, 4) и вычисляет новый `id = 5`.
   - Создаётся словарь:
     ```python
     new_record = {
         "id": 5,
         "title": "Совершенный код",
         "category": "Программирование",
         "amount": 600,
         "completed": False
     }
     ```
   - Запись добавляется в текущий список `records.append(new_record)`.
3. **Сохранение в JSON (`storage.py`)**:
   - При выборе сохранения вызывается `save_records(data_path, records)`.
   - Сначала вызывается `validate_records(records)`, подтверждающий типы всех полей.
   - Затем открывается файл `data.json` в кодировке UTF-8 и сериализуется через `json.dump(records, f, ensure_ascii=False, indent=2)`. В файле логическое `False` преобразуется в `false`.
4. **Обратная загрузка (`storage.py` $\rightarrow$ `main.py`)**:
   - При следующем запуске `main.py` вызывает `load_records(data_path)`.
   - `json.load(f)` десериализует файл: `false` превращается в булево `False` языка Python.
   - Проводится полная валидация структуры.
   - Запись готова к отображению в таблице, поиску и статистике.
