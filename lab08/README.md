## Ответы на вопросы и обоснование решений

### Почему запись удобно представить словарём
Словарь (`dict`) хранит пары «ключ-значение», что позволяет обращаться к полям объекта по понятным семантическим именам (`record["title"]`, `record["hours"]`), а не по числовым индексам. Это устраняет зависимость от порядка следования полей, снижает вероятность ошибок при расширении структуры (например, при добавлении поля `completed: False`) и делает код самодокументируемым.

### Выбор структуры данных для задач
1. **Частоты слов (`dict`)**: словарь сопоставляет уникальное слово (ключ) и количество его вхождений (значение), обеспечивая быстрый поиск $O(1)$ и удобное обновление через метод `.get()`.
2. **Учебные интересы (`set`)**: множество гарантирует хранение только уникальных тем и предоставляет компактные операции пересечения `&` (общие интересы) и объединения `|` (все уникальные интересы).
3. **Запись и пара (`dict` и `tuple`)**: запись объединяет изменяемые разнородные поля объекта, а кортеж фиксирует неизменяемую пару значений фиксированной длины для безопасной передачи и распаковки (`name, count = pair`).
4. **Каталог книг (`list` словарей)**: список сохраняет порядок добавления записей и допускает повторы, а вложенные словари представляют отдельные структурированные карточки книг.

### Поведение метода `.get()`
Прямое обращение по несуществующему ключу `dict[key]` вызывает ошибку `KeyError`. Метод `dict.get(key, default)` возвращает значение по ключу, если он найден, либо возвращает запасное значение `default` (по умолчанию `None`), если ключ отсутствует. В подсчётах `counts[word] = counts.get(word, 0) + 1` это позволяет инициализировать счётчик нулём при первом появлении слова без предварительной проверки через `if`.

### Причина сортировки множества перед выводом
Элементы множества (`set`) не имеют гарантированного порядка, так как их позиция зависит от хеш-значений и рандомизации хеширования строк в Python. Чтобы результат был детерминированным, предсказуемым и воспроизводимым в тестах, перед выводом к множеству применяется функция `sorted()`, упорядочивающая элементы по алфавиту.

### Двухкритериальная сортировка категорий через `key`
В функции `sorted_category_totals` список пар `(category, total)` сортируется сначала по убыванию суммы, а при равных суммах — по возрастанию названия категории. Это достигается с помощью аргумента:
```python
key=lambda item: (-item[1], item[0])
```
где `-item[1]` обращает порядок числовой суммы для сортировки по убыванию, а `item[0]` сортирует строки по алфавиту в естественном порядке возрастания.

## Проверки

### 1. word_counts(text)

Правила:
- Приведение всего текста к нижнему регистру.
- Разбиение по пробельным символам.
- Удаление знаков препинания `.,!?;:` по краям слов (`strip(".,!?;:")`).
- Пропуск пустых строк, оставшихся после очистки.
- Возврат словаря «слово → количество вхождений».

#### Таблица «ввод → ожидаемый ответ → фактический ответ»

| Ввод | Описание проверки | Ожидаемый ответ | Фактический ответ |
|---|---|---|---|
| `Python, python! SQL` | Контрольный пример из методички | `{"python": 2, "sql": 1}` | `{"python": 2, "sql": 1}` (совпадает) |
| `!!!` | Строка только из знаков препинания | `{}` | `{}` (совпадает) |
| `""` | Пустой ввод | `{}` | `{}` (совпадает) |
| `один один два. ДВА? два` | Разный регистр и знаки пунктуации | `{"один": 2, "два": 3}` | `{"один": 2, "два": 3}` (совпадает) |

#### Проверка 1 — контрольный пример `Python, python! SQL`
- `Python,` $\rightarrow$ очистка: `python`, частота: 1
- `python!` $\rightarrow$ очистка: `python`, частота: 2
- `SQL` $\rightarrow$ очистка: `sql`, частота: 1
- Итог: `{"python": 2, "sql": 1}`. Фактический результат совпадает.

### 2. common_topics(first, second) и all_topics(first, second)

Правила:
- `common_topics` находит общие элементы через пересечение множеств `set(first) & set(second)`.
- `all_topics` объединяет все элементы через `set(first) | set(second)`.
- Результаты возвращаются отсортированными списками.

#### Таблица «ввод → ожидаемый ответ → фактический ответ»

| Список 1 | Список 2 | Операция | Ожидаемый ответ | Фактический ответ |
|---|---|---|---|---|
| `["python", "sql", "python"]` | `["sql", "git"]` | Общие темы | `["sql"]` | `["sql"]` (совпадает) |
| `["python", "sql", "python"]` | `["sql", "git"]` | Все темы | `["git", "python", "sql"]` | `["git", "python", "sql"]` (совпадает) |
| `[]` | `["sql", "git"]` | Общие темы | `[]` | `[]` (совпадает) |
| `[]` | `["sql", "git"]` | Все темы | `["git", "sql"]` | `["git", "sql"]` (совпадает) |
| `[]` | `[]` | Все темы | `[]` | `[]` (совпадает) |

#### Проверка 1 — контрольные темы
- $A = \{\text{python}, \text{sql}\}$, $B = \{\text{sql}, \text{git}\}$
- Пересечение $A \cap B = \{\text{sql}\}$, после сортировки: `["sql"]`
- Объединение $A \cup B = \{\text{git}, \text{python}, \text{sql}\}$, после сортировки: `["git", "python", "sql"]`

### 3. demo_record() — словарь и кортеж

- Создание: `{"title": "Python", "hours": 4}`
- Модификация: `hours = 6`, добавление `completed = False`
- Формирование кортежа: `("Python", 6)`
- Распаковка кортежа: `name, count = pair` $\rightarrow$ `name = "Python"`, `count = 6`.

Фактический результат:
```
Запись: {'title': 'Python', 'hours': 6, 'completed': False}
Пара из кортежа: Python, 6
```
совпадает с ожидаемым.
