## Описание формата данных

### Входной файл `matrix.txt`
- Файл сохраняется в кодировке **UTF-8**.
- **Строка 1**: два положительных целых числа через пробел — количество строк $R$ и столбцов $C$.
- **Последующие $R$ строк**: ровно по $C$ целых чисел в каждой строке, разделенных пробелами.
- После последней строки данных допускается ровно один стандартный перевод строки `\n`.
- Любые пустые строки внутри данных, лишние строки в конце, недостаток или избыток чисел вызывают исключение `ValueError` с указанием номера проблемной строки.

Пример `matrix.txt`:
```text
2 3
1 -2 3
4 0 -6
```

### Выходной файл отчёта `report.txt`
Файл формируется в кодировке **UTF-8** и содержит три строки:
1. `Суммы строк:` — суммы элементов по каждой строке через пробел.
2. `Суммы столбцов:` — суммы элементов по каждому столбцу через пробел.
3. `Результат варианта:` — сумма отрицательных элементов матрицы (Вариант 2).

Пример `report.txt`:
```text
Суммы строк: 2 -2
Суммы столбцов: 5 -2 -3
Результат варианта: -8
```

## Ответы на вопросы и обоснование решений

### Отличие ошибок формата от ошибок доступа
- **Ошибки доступа** (`FileNotFoundError`, `PermissionError`, `OSError`) возникают на уровне операционной системы до чтения содержимого файла. Причины: файл не найден по указанному пути, отсутствуют права на чтение или запись, файл занят другим системным процессом или повреждена файловая система.
- **Ошибки формата** (`ValueError`, `UnicodeDecodeError`) возникают после успешного открытия файла в процессе разбора его содержимого. Причины: файл пуст, повреждена кодировка UTF-8, заголовок содержит не два числа, строка содержит меньше/больше значений, чем объявлено в заголовке, либо значение не преобразуется в целое число (`int`).

### Почему отчёт открывается для записи только после проверки входа
Открытие файла в режиме `'w'` (`open(..., 'w')`) немедленно усекает (стирает) всё прежнее содержимое файла ещё до того, как в него будет записан хотя бы один байт. Если открыть файл отчёта до или в процессе разбора входных данных, то любая ошибка формата или сбой чтения приведёт к тому, что старый отчёт окажется безвозвратно уничтожен, а новый так и не будет сформирован.

Поэтому в архитектуре программы чтение, валидация и все вычисления проводятся заранее в оперативной памяти. Файл отчёта открывается на запись только тогда, когда гарантирована стопроцентная корректность всех данных.

### Проверка сохранности старого отчёта при ошибке входа
В тесте `test_old_report_preserved_on_error` модуля `test_files.py` реализована проверка:
1. В каталоге создаётся файл `report.txt` с контрольным текстом `ПРЕЖНЕЕ СОДЕРЖИМОЕ ОТЧЕТА`.
2. Программе передаётся заведомо некорректный файл матрицы (строка с буквой `1 x`).
3. Чтение матрицы выбрасывает `ValueError`.
4. Блок записи отчёта не вызывается.
5. Проверяется, что `report.txt` сохранил прежнее содержимое символ в символ.

## Проверки

### 1. read_positive_integer() в main.py

Правила:
- При вводе нечисловых символов выводится: `Ошибка: не целое число`.
- При вводе чисел $\le 0$ выводится: `Ошибка: должно быть больше нуля`.
- Цикл завершается только при вводе целого числа $> 0$.

#### Таблица «ввод → реакция программы»

| Ввод | Тип проверки | Вывод программы | Статус |
|---|---|---|---|
| `abc` | Строка текста | `Ошибка: не целое число` | Повтор запроса |
| `0` | Граничное нулевое значение | `Ошибка: должно быть больше нуля` | Повтор запроса |
| `-2` | Отрицательное число | `Ошибка: должно быть больше нуля` | Повтор запроса |
| `3` | Корректное положительное целое | Принято число: `3` | Успешное завершение |

### 2. read_matrix(path) в files_lab.py

#### Таблица «входные данные → ожидаемое поведение → фактический результат»

| Содержимое файла | Описание проверки | Ожидаемый результат | Фактический результат |
|---|---|---|---|
| `2 3\n1 -2 3\n4 0 -6\n` | Контрольный файл `matrix.txt` | `[[1, -2, 3], [4, 0, -6]]` | `[[1, -2, 3], [4, 0, -6]]` (совпадает) |

| `1 1\n0\n` | Матрица 1x1 с нулем | `[[0]]` | `[[0]]` (совпадает) |
| `""` | Пустой файл | `ValueError("Файл пуст")` | `ValueError` (совпадает) |
| `0 3\n` | Нулевое количество строк в заголовке | `ValueError` (числа должны быть > 0) | `ValueError` (совпадает) |

| `1 1\n0\n1\n` | Лишняя строка данных | `ValueError` (неверное количество строк данных) | `ValueError` (совпадает) |
| `1 1\n0\n\n` | Лишняя пустая строка в конце | `ValueError("Обнаружена лишняя пустая строка...")` | `ValueError` (совпадает) |
| Отсутствующий файл | Несуществующий путь | `FileNotFoundError` | `FileNotFoundError` (совпадает) |

### 3. selected_sum(matrix) — Вариант 2: отрицательные элементы

Правила:
- Суммируются только элементы, строго меньшие нуля ($x < 0$).
- Если отрицательных элементов нет, возвращается `0`.

#### Ручной расчёт для `matrix.txt`:
$$\text{Матрица: } \begin{pmatrix} 1 & -2 & 3 \\ 4 & 0 & -6 \end{pmatrix}$$
- Отрицательные элементы: $-2$ и $-6$.
- Сумма: $(-2) + (-6) = -8$.

#### Таблица проверок

| Матрица | Описание | Ожидаемый ответ | Фактический ответ |
|---|---|---|---|
| `[[1, -2, 3], [4, 0, -6]]` | Контрольная матрица | `-8` | `-8` (совпадает) |
| `[[1, 2], [3, 4]]` | Только положительные | `0` | `0` (совпадает) |
| `[[-5, -10], [-1, -2]]` | Все отрицательные | `-18` | `-18` (совпадает) |
| `[]` | Пустая матрица | `0` | `0` (совпадает) |
