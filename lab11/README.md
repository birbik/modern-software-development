## Ответы на вопросы и обоснование решений

### Разница между форматами JSON и структурами Python
1. **Булевы значения и null**:
   - В JSON используются ключевые слова `true`, `false` и `null` (в нижнем регистре).
   - В Python им соответствуют константы `True`, `False` и `None`.
2. **Ключи словарей**:
   - В JSON ключи объектов всегда обязаны быть строками в двойных кавычках (`"key": value`). Одинарные кавычки в JSON не допускаются.
   - В Python ключами словаря могут быть любые хешируемые типы (числа, кортежи, строки), а строковые литералы могут оформляться как одинарными, так и двойными кавычками.
3. **Кортежи**:
   - При сериализации в JSON кортеж `tuple` преобразуется в массив (`[]`). При обратной десериализации он восстанавливается как список `list`.

### Почему `json.JSONDecodeError` должен обрабатываться раньше `ValueError`
Класс `json.JSONDecodeError` является прямым потомком `ValueError` (`issubclass(JSONDecodeError, ValueError) is True`).

В блоке `try...except` интерпретатор Python проверяет обработчики сверху вниз до первого совпадения типа исключения. Если поставить `except ValueError:` выше `except json.JSONDecodeError:`, то любые синтаксические ошибки повреждённого JSON-файла будут перехвачены общим обработчиком `ValueError`, а специализированный обработчик `JSONDecodeError` никогда не выполнится.

### Назначение параметров и заголовков HTTP-запроса
- **URL (`https://api.github.com/users/{login}`)**: адрес конечной точки REST API GitHub, возвращающей данные публичного профиля конкретного пользователя. Функция `quote(login.strip(), safe="")` экранирует спецсимволы в логине, защищая запрос от некорректного URL.
- **Метод GET**: стандартный метод HTTP для чтения данных. Он не изменяет состояние на сервере (является безопасным и идемпотентным).
- **Таймаут (`timeout=10`)**: ограничение времени ожидания ответа сервера в 10 секунд. Защищает приложение от бесконечного зависания при разрыве соединения, потере пакетов или перегрузке сервера.
- **Заголовок `Accept` (`application/vnd.github+json`)**: сообщает серверу, что клиент ожидает ответ в формате JSON в соответствии со спецификацией GitHub REST API v3.
- **Заголовок `User-Agent` (`python-course-lab11`)**: обязательное требование API GitHub. Без указания имени приложения сервер возвращает ошибку `HTTP 403 Forbidden`.
- **Обработка сетевых ошибок**:
  - `HTTPError`: ошибки сервера (например, 404 — пользователь с таким логином не существует, 403 / 429 — исчерпан лимит запросов);
  - `URLError`, `TimeoutError`, `socket.timeout`: неполадки сети, отсутствие интернет-подключения, ошибки DNS или истечение таймаута;
  - При недоступности сети программа предлагает переключиться на локальный файл `profile_sample.json`.

## Проверки

### 1. Валидация todos.json (функция validate_todos)

Правила:
- Корень — список объектов `list`.
- Поля `id` и `userId` — строго целые положительные числа (`type(val) is int and val > 0`). Это исключает значение `True`, которое формально является подклассом `int`.
- Поле `title` — непустая строка.
- Поле `completed` — булево значение (`type(val) is bool`).
- Идентификаторы `id` уникальны во всем файле.

#### Таблица проверок валидации

| Ситуация | Ожидаемое поведение | Фактический результат |
|---|---|---|
| Контрольный набор `todos.json` | Успешная валидация (`True`) | `True` (совпадает) |
| Объект `{}` вместо списка | `ValueError("Корневой элемент данных должен быть списком")` | `ValueError` (совпадает) |
| Повторяющийся `id` | `ValueError` с сообщением о неуникальном `id` | `ValueError` (совпадает) |
| Отсутствующее поле `userId` | `ValueError` с указанием отсутствующего поля | `ValueError` (совпадает) |
| Строка вместо bool: `completed="false"` | `ValueError` (поле должно быть логическим) | `ValueError` (совпадает) |
| Логическое значение в ID: `id=True` | `ValueError` (поле должно быть целым числом) | `ValueError` (совпадает) |
| Пустая строка `title="   "` | `ValueError` (поле должно быть непустой строкой) | `ValueError` (совпадает) |

### 2. Подсчёт завершённых задач и лидеры

Учебный набор:
- Задача 1: `userId=5`, `completed=true` $\rightarrow$ пользователь 5: 1
- Задача 2: `userId=5`, `completed=false`
- Задача 3: `userId=10`, `completed=true` $\rightarrow$ пользователь 10: 1
- Задача 4: `userId=10`, `completed=true` $\rightarrow$ пользователь 10: 2
- Задача 5: `userId=5`, `completed=true` $\rightarrow$ пользователь 5: 2

Итог подсчёта `completion_counts`: `{5: 2, 10: 2}`.  
Максимальное количество выполненных задач равно 2.  
Лидеры `top_users`: `[5, 10]`.  
Завершённые задачи лидеров `get_leader_tasks`: задачи с ID `[1, 3, 4, 5]`.

#### Таблица проверок лидеров

| Набор данных | `completion_counts` | `top_users` | `get_leader_tasks` (ID) |
|---|---|---|---|
| Контрольный `todos.json` | `{5: 2, 10: 2}` | `[5, 10]` | `[1, 3, 4, 5]` (совпадает) |
| Пустой список `[]` | `{}` | `[]` | `[]` (совпадает) |
| Только незавершённые задачи | `{1: 0, 2: 0}` | `[]` | `[]` (совпадает) |
| Пользователь 1 (2 задачи), пользователь 2 (1 задача) | `{1: 2, 2: 1}` | `[1]` | `[1, 2]` (совпадает) |
